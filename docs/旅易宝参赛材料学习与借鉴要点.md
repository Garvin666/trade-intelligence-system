## 4. 值得学习的具体写法

### 4.1 痛点页：每条痛点配数字和来源

旅易宝的痛点页不是空喊“体验不好”，而是每条配一个量化数据，页面底部统一标注报告名称：

- 超过 70% 老年人认为现有旅游产品不适合（《中国老年旅游发展报告》）
- 超 60% 用户实际消费超预算（携程《旅游消费趋势报告》）
- 仅不到 10% 平台提供无障碍设施信息（中国残联数据）

当前项目建议把痛点同样量化，例如：跨境电商进出口 2.75 万亿元但中小卖家缺少数据团队；美国取消 de minimis 免税后小额包裹到岸成本变化；选品/关税/汇率/合规/物流分散在多平台。每个数字必须能说出处（海关总署、商务部、平台公告、行业报告），不确定来源的数字不写。

### 4.2 市场规模：总规模 → 细分市场 → 潜在规模

旅易宝的推导链是：国内旅游 6.5 万亿 → 在线旅游 1.3 万亿 → 个性化定制 2000 亿 / 特殊人群 1000 亿 / 企业团体 1500 亿 → 本项目潜在规模约 275 亿。

当前项目建议写：跨境电商 2.75 万亿 → 服务商/工具市场占比 → 目标客群（中小卖家数量 × 客单价）→ TAM/SAM/SOM，并注明每年增长率和来源。评委追问时，这套推导链比单摆一个“2.75 万亿”更可信。

### 4.3 目标用户：核心 / 高附加值 / 潜在三层

旅易宝把用户分成核心客户（流量入口）、高附加值客户（客单价和稳定收入）、潜在客户（品牌传播），每类写特征和需求。

当前项目建议对应为：核心客户是中小跨境卖家（高频、量大）；高附加值客户是外贸企业、品牌出海团队（定制咨询、API）；潜在客户是供应链服务商、金融机构/园区（远期数据信用、供应链金融）。

### 4.4 竞品：多维矩阵，而不是三行表

旅易宝用“功能维度 × 竞品 × 本项目”的矩阵表，列出特殊人群、动态预算、社交媒体整合、线下服务对接、天气自适应等维度，用 √/× 直接看出差异。

当前项目的竞品表只有 3 行，建议升级为：维度（多源选品、政策监控、到岸成本、合规准入、IP 筛查、物流测算、多语言舆情、数据信用）× 竞品（卖家精灵、Jungle Scout、自建表格） × 本项目。

### 4.5 业务逻辑：画闭环

旅易宝用“产品设计 → 市场推广 → 产品销售 → 生产管理 → 物流运输 → 安装调试 → 售后服务 → 数据反哺”闭环图，说明项目不是单点功能。

当前项目建议画两条闭环：

- 产品闭环：多源数据 → 趋势预测 → 选品推荐 → 贸易测算 → 决策建议 → 用户反馈 → 数据回流
- 商业闭环：免费/试用获客 → 激活 → 付费订阅 → 留存 → 数据反哺模型 → 提高付费价值

### 4.6 技术路线：分模块，不堆概念

旅易宝把技术路线分成数据获取与整合、AI 算法、多语言与货币换算、云服务与部署、安全与隐私五块，每块 2-3 句话。

当前项目已有清晰流水线图，建议补上“数据合规与安全”（官方 API、脱敏、权限）和“部署与可复现”（Docker/FastAPI、固定随机种子、指标落盘），这样和现有 106 项测试、对照组实验形成工程证据链。

### 4.7 创新点：按产品/技术/服务/商业模式四类

旅易宝的创新章分为四类，每类 2 条左右，避免“一条创新点一长段”。

当前项目现有 6 条创新点，建议重排：

| 类型 | 建议表述 |
| --- | --- |
| 产品创新 | 多源选品 + 贸易决策一体化看板 |
| 技术创新 | 双模型预测对比（MAPE 2.29% vs 3.36%）、可解释评分 |
| 服务创新 | 中文推荐理由、政策预警与应对建议 |
| 商业模式创新 | SaaS 订阅 + 报告 + API + 远期数据信用分润 |

> 口径注：上表“技术创新”中的 MAPE（2.29% vs 3.36%）基于合成快照 + 轻量对照组，外部代表性待真实数据复核。

### 4.8 盈利模式：收入结构 + 成本控制 + 可持续性

旅易宝给出收入来源占比（广告 45%、会员 30%、数据 15%、生态服务 10%），再写成本控制（技术外包、精准投放、动态分成）和可持续性（复购、数据边际成本递减、生态协同）。

当前项目建议写清：

- 收入：SaaS 订阅、行业报告、API 服务、定制咨询，各占多少并给依据（对标同类 SaaS 定价）
- 成本：算力、数据、人力、推广、合规认证
- 可持续：数据越用越准、客户续费、API 边际成本低

注意不要写“3 年营收突破 5 亿”这类没有推导依据的口号（详见第 6 节避坑）。

### 4.9 财务：三年预测 + 敏感性 + 对标依据

旅易宝财务章最完整，包含：

- 资金来源与股权分配表（金额、来源、股权占比、用途、注入阶段）
- 分年成本明细表
- 3 年收入/成本/净利润表
- 敏感性分析（用户增长 +20% / -30% 时净利润变化）
- 可行性措施（获客保障、成本控制、收入多元化、风险预案）

当前项目 `商业计划书.md` 的财务预估只有一段话，是本次借鉴中最值得补的部分。建议按“大创预算（5000 元，已有）”和“创业假设（SaaS 3 年预测）”两套口径分开写，避免混淆。

### 4.10 风险：四类风险 + 应急预案

旅易宝把风险分为技术、运营、市场与竞争、法律与合规四类，每条写“风险 + 规避措施”，最后单独加应急预案（系统故障、突发事件）。

当前项目已有风险表，建议升级为：

| 类别 | 示例风险 | 规避/触发阈值 |
| --- | --- | --- |
| 技术 | 模型泛化不足、数据源不稳定 | 滚动回测、多模型对比、MAPE 阈值 |
| 运营 | 真实用户不足、留存低 | 20-50 份问卷、留存率阈值 |
| 市场 | 成熟竞品、平台数据获取受限 | 差异化维度矩阵、官方 API 优先 |
| 合规 | 数据隐私、知识产权 | 脱敏、授权、仅官方公开数据 |
| 应急 | 演示环境故障 | 单文件 HTML 离线兜底、备用截图 |

### 4.11 发展规划：业务目标，不只是技术 Roadmap

旅易宝按短期（1-2 年）、中期（3-5 年）、长期（5 年以上）写发展目标，再写发展阶段和预期成果。

当前项目 Roadmap 只写了技术迭代，建议补业务目标：

- 短期：原型验证、20-50 份问卷、3-5 位卖家访谈、接入小样本真实数据
- 中期：SaaS 看板上线、月度品类报告、企业试用
- 长期：API 服务、供应链数据、数据信用/供应链金融

### 4.12 团队与指导老师：角色 + 量化成绩

旅易宝每位成员写“角色 + 职责 + 一项量化成绩”，指导老师写职称、研究方向、项目和论文成果。

当前项目 `大创项目申报书.md` 的团队信息全部是“待填写”，建议按同一格式补：负责人、数据分析、算法建模、前后端、文档调研五类角色，每人写 GPA/比赛/技能/项目贡献；指导老师补跨境电商、国际贸易或计算机方向成果。

### 4.13 每页标注数据来源

旅易宝 PPT 几乎每页底部都写“具体数据来源：……”，BP 正文数字也尽量给报告名。当前项目材料的数据大多没有标来源，建议统一在 PPT 底部和 BP 表格下加“数据来源：海关总署 / 商务部 / 平台公告 / 行业报告（日期）”。

## 6. 不要照抄的坑

旅易宝这份材料在“参赛完整性”上值得学，但有几处硬伤，当前项目要避免：

1. 内部口径不一致：旅易宝收入预测是第 1-3 年 50/400/1200 万元，正文却写“3 年内年营收突破 5 亿元”；成本章写 1100/1030/940 万元，成本明细表却合计 1210/1172/1100 万元。评委翻到对应页会直接质疑。
2. 部分数字无出处：市场规模、增长率、用户占比写了很多，但并非每个数字都有可追溯来源。当前项目应只保留能说明来源的数字。
3. 财务过于理想：旅易宝用“对标美团抽成 4%”“对标 Wanderlog”等方式解释预测，但整体仍偏乐观。当前项目建议明确“演示口径”和“真实验证计划”，用 106 项测试、对照组实验等工程证据支撑可信度。
4. 概念堆砌：功能和技术名词很多，但缺少用户验证。当前项目材料已较好地区分“已实现演示版”和“远期规划”，继续坚持这个口径。
5. 团队叙事脱离专业：旅易宝强调“全部由大一学生组成”是卖点，但当前项目如果缺少跨境电商/国际贸易背景，应写“数据、算法、产品、商业四类角色 + 相关专业顾问”，不要硬套学生身份叙事。
