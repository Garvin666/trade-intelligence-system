## 二、阻断级问题（答辩前建议优先处理）

### B1. 政策事件未标注品类 → 无关政策污染所有品类的决策结果（实测）

- **证据**：`src/trade/policy.py:954-973` 的 `applicable_events_for()` 逻辑为"若事件标注了 categories 且不含当前品类则跳过"。实测 `load_policy_events()` 返回的 **23 个政策事件中 0 个带 categories**（`with_categories=0`），该过滤条件永远不生效。
- **影响（实测）**：贸易决策页"智能宠物喂食器 × 美国"的报告中，`核心结论` 把"越南冷冻鱼片反倾销""印度大豆粕反倾销""韩国钢丝反倾销"等**与宠物用品完全无关**的事件全部列入"已生效"，有效税率从 6% 被抬到 **126%**、毛利率 -196.4%、决策 31.4 分"暂缓进入"。评委若抽查任一组合即会发现决策被无关政策驱动，严重损害可信度。
- **修复方向**：
  1. 为每个政策事件补 `categories` 字段（`src/trade/policy.py` 内嵌事件表与 `output/policy/latest.json` 的候选事件），至少标注主要受影响品类；
  2. `applicable_events_for` 中把"categories 为空"的事件**只用于市场级提醒、不参与税率重算**；
  3. 决策报告"核心结论"里把政策事件按"与本组合相关/仅市场级"分组展示。

### B2. 数据口径自相矛盾：46 品类 / 690 组合 / 71,760 行 / 717,120 行 四套数字并存（实测 + 审计）

- **证据**：
  - 源码 `src/config.py` 实测 **66 个品类**（66×15×104=102,960 行，与 `data/processed/clean_data.csv` 一致）；
  - 但运行中的后端 `/api/categories`、`/api/summary` 实测返回 **46 个品类、推荐 690 行（46×15）**——是 9:03 启动的**旧代码进程**（见 B3）；
  - `frontend/src/widgets/MetricsGrid.tsx:27` 的提示文案写死"四十六大跨境品类"，与 API 动态值并列显示；
  - `docs/技术文档.md:173` 写"717,120 条周粒度数据（46 品类 × 15 市场 690 组合）"；`docs/Demo优缺点评估报告.md:128` 写"71,760 行"（两者差 10 倍）；`docs/商业计划书.md:39` 还出现"60 组"。
- **影响**：任何一份材料被评委与代码/看板核对都会穿帮；看板"覆盖品类 46"与"66 大品类"宣传互相矛盾。
- **修复方向**：以 `len(CATEGORIES)` 为唯一事实源，一次性批量替换 docs 为 **66 品类 × 15 市场 = 990 组合、102,960 行**；MetricsGrid 的 hint 改为动态生成；核对并停掉旧进程（B3）。

### B3. 旧代码进程长期占用 8000 端口，新代码不生效（实测）

- **证据**：8000 端口被 `C:\Users\26717\anaconda3\python.exe scripts/run_api.py`（PID 15112，9:03:58 启动）占用；该进程返回 46 品类（旧代码口径）。另有 `E:\大创\.venv\Scripts\python.exe` 的 run_api.py 进程（PID 27888）**未监听任何端口**（疑似启动时端口被占后挂起），其日志 `tmp/complete-demo-backend.err.log` 记录了 `GET /api/dashboard-data?category=pet&market=us` 的 500（`KeyError: 'model'`，当前源码 `services.py:184` 已修复该缺陷）。`start_complete_demo.ps1:190-222` 检测到 8000 健康就直接复用、不重启 → **用户改完代码双击启动，看到的仍是旧版本**。
- **影响**：演示现场若曾残留旧进程，前端展示与新代码/新文档不一致（46 vs 66），且修复过的 bug 依然可见。
- **修复方向**：
  1. 启动脚本在 `Test-Health` 命中后增加"代码版本指纹"比对（如对比 `src/config.py` 的 CATEGORIES 数量或启动时间戳），不一致则提示并重启；
  2. 提供一键清理：`stop_complete_demo.ps1` 应同时清理所有 `run_api.py` 进程（按命令行匹配，而不只是 pid 文件）；
  3. 发布包与根目录共用同一套端口检测，避免多副本并存。

## 三、重要级问题

### I1. 首屏/筛选性能：全量数据下发 6MB+，离线包内联 53MB JSON

- **证据（实测）**：看板首屏 `GET /api/dashboard-data` 返回 **6,245,954 字节**，`/api/search/trends`、`/api/competition/index` 等单接口耗时 1.2–2.2s；`output/dashboard-data.json` 53.09MB；`output/app-offline.html` 56.43MB（`frontend/vite.config.ts:41-43` 把整个 JSON 内联进 HTML）。切换筛选会触发 `useMarketIntel` 8 路并行全量接口（`frontend/src/shared/api/hooks.ts:230-250`）。
- **修复方向**：看板改服务端聚合（只下发图表所需聚合序列）；离线版把数据拆成独立 `.json` 文件用 fetch/IndexedDB 加载，不再内联 50MB+ 脚本；筛选接口默认带 `limit` 与分页。

### I2. 安全面：API 全无鉴权 + CORS `*` + API Key 明文存 localStorage

- **证据**：`src/api/app.py:34-38` 默认 `allow_origins=["*"]`，70+ 端点（含收 Key 的 `POST /api/ai/config`、触发重任务的 `POST /api/jobs/*/start`、改权重的 `POST /api/scoring/weights`）均无鉴权；`frontend/src/features/ai-config/AiConfigPanel.tsx:200` 把 Key 明文写入 `localStorage`。`src/api/ai_config.py` docstring 声称"never written to disk or returned to clients"，与前端 localStorage 持久化直接矛盾。
- **修复方向**：演示场景至少加一个随机启动 token 的简单鉴权中间件（或绑定 127.0.0.1 时限制 Origin）；`/api/ai/config` 保持脱敏返回；文档声明"仅本机演示、勿填真实付费 Key"。

### I3. 全局异常处理器吞掉 traceback，500 无日志可查

- **证据**：`src/api/app.py:908-917` 的 `@app.exception_handler(Exception)` 返回通用 500 但**无任何 logging/traceback**，真实堆栈丢失（本次审计若非 err.log 恰好有 pandas traceback，B3 的 500 根因将不可见）。
- **修复方向**：处理器内先 `logger.exception(...)` 再返回 500。

### I4. 四脑/联网/回退核心用例在项目主平台 Windows 上整体跳过

- **证据**：`tests/test_api.py:416,431,454,491,507,523`、`tests/test_search_api.py:55,77`、`tests/test_ai_speed.py:17` 共 9 处 `skipif(sys.platform == "win32")`，而本项目全套脚本（.bat/PowerShell/Streamlit）都以 Windows 为目标——即主平台上四脑引擎、联网研究、AI 回退从未被执行过。
- **修复方向**：定位"四脑图表原生访问冲突"根因（疑似 plotly 图表序列化）后按用例修复；至少增加 GitHub Actions（Linux 全量跑）+ `pytest -m "not win_skip"` 统计口径。

### I5. 推荐排序前端/后端双实现，存在结果漂移

- **证据**：Top-N 排序（verdict 序→六维分→增长→趋势→字典序 tiebreak）在 `src/api/services.py:633-641` 与 `frontend/src/entities/dashboard/model.ts:47-65` 各实现一遍；`VERDICT_ORDER` 在 `src/models/recommend.py:11`、`src/api/services.py:79`、`frontend/src/entities/dashboard/model.ts:14` 重复定义 3 处。
- **修复方向**：排序收敛到后端 `recommendations` 接口返回已排序 Top-N，前端只展示；VERDICT_ORDER 由后端下发。

### I6. 汇率魔法数字漂移：7.15 vs 7.1

- **证据**：`src/trade/cost.py:11`（`DEFAULT_FX_RATE = 7.15`）vs `frontend/src/shared/api/client.ts:558,576`（离线回退写死 `* 7.1`）。
- **修复方向**：前端从 `/api/catalog` 或配置接口下发汇率，删除离线分支硬编码。

### I7. 系统控制台渲染缺陷：多处显示 `[object Object]`（实测）

- **证据**：`frontend/src/features/system/SystemOverview.tsx:185` 对非数字值直接 `String(value)`，嵌套对象（如 `system_eval.prophet`、`coverage`、`capabilities.policy_cost`）渲染成 `[object Object]`。实测"系统评测""能力状态"两块不可读。
- **修复方向**：`SummaryBlock` 增加对象递归渲染（缩进/JSON 预览），或后端把 `model_summary`/`system_eval` 拍平成标量。

### I8. 上传功能与 64KB 体积上限冲突

- **证据**：`src/api/middleware.py:15` 对**所有**请求按 `Content-Length > 65536` 直接 413；而"上传用户 CSV/JSON 仅基于用户数据生成报告"是 AGENTS.md 主推特性，真实 CSV 极易超 64KB；且只查 Content-Length（chunked 可绕过），`/api/eda` 整文件读入内存。
- **修复方向**：上传端点单独放宽限额并流式读取、限制行数；中间件补 Transfer-Encoding 检查。

### I9. 环境自检"未通过" + 首次请求超时（实测）

- **证据**：`GET /api/check` 实测结果 `ok=30 warn=1 fail=1`，fail 项为"依赖缺失：fg-data-profiling、scikit-posthocs、pyod"（当前 8000 进程运行在 anaconda 环境、缺这 3 个 requirements.txt 声明包）；首次调用耗时超 20 秒（疑似首次加载较重）。页面"环境自检"页签首次切换空白、第二次正常（React Query 缓存时序问题）。
- **修复方向**：统一用 `.venv` 启动并补齐 3 个依赖；`/api/check` quick 档去掉重量级检查或加 `lru_cache`；修复页签首次空白（首屏预取该 query）。

### I10. 演示页多处 "--" 占位（实测）

- **证据**：贸易决策报告中"汇率敏感性"三档全为 `--%`、"物流三方案"方案名全为 `--`、"尽调就绪"为 `--`；市场情报"平台榜单"标题/价格/评分全为 `--`、"评论增长"全为 `--`（离线 mock 所致，`src/trade/report.py` 与对应 API 未填演示值）。
- **修复方向**：为演示口径补齐缺省值或明确标注"离线未取到数据"；答辩演示时优先选用数据完整的组合。
