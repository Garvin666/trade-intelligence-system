## 二、重要级问题

### F1. 系统控制台渲染缺陷：多处显示 `[object Object]`（实测）

- **证据**：`frontend/src/features/system/SystemOverview.tsx:185` 对非数字值直接 `String(value)`，嵌套对象（如 `system_eval.prophet`、`system_eval.coverage`、`capabilities.policy_cost`）渲染成 `[object Object]`。实测"系统评测"卡片里 `prophet: [object Object]`、`lightgbm: [object Object]`，"能力状态"里 `policy_cost: [object Object]`——整块不可读。
- **修复方向**：`SummaryBlock` 增加对象递归渲染（嵌套缩进或 JSON 预览），或后端把 `model_summary`/`system_eval` 拍平成标量后下发。

### F2. 首屏与筛选性能：全量数据 + 8 路并行（实测）

- **证据**：看板首屏 `GET /api/dashboard-data` 实测返回 **6,245,954 字节**；`/api/search/trends` 2.2s、`/api/competition/index` 1.9s、`/api/dashboard-data` 1.7s（均含全量数据框过滤，`src/api/services.py:973-1005`）；切换品类/市场筛选触发 `useMarketIntel`（`frontend/src/shared/api/hooks.ts:230-250`）**8 路并行全量接口**，且前端 `filterHistory`（`frontend/src/entities/dashboard/model.ts:16-22`）对全量 history 再过滤。
- **修复方向**：看板改为服务端聚合（只下发图表所需聚合序列）；筛选接口默认带 `limit`/分页；前端按需请求 `/api/history?category=&market=`。

### F3. 离线单文件体积过大：56MB HTML 内联全量数据

- **证据**：`output/app-offline.html` 56.43MB、`output/dashboard-offline.html` 54.60MB；`frontend/vite.config.ts:41-43` 将整个 `output/dashboard-data.json`（53.09MB）以 `<script>window.__TRADE_INTEL_OFFLINE__=...` 内联进 HTML，浏览器解析与首屏渲染会明显卡顿。
- **修复方向**：离线版把数据拆为独立 `.json` 文件，用 fetch/IndexedDB 加载；或离线版默认只内联概览/图表聚合数据。

### F4. API Key 明文存 localStorage（安全）

- **证据**：`frontend/src/features/ai-config/AiConfigPanel.tsx:200` 将用户填入的 API Key 明文写入 `localStorage`（key 名 `yuanfan-ai-config`，见 `frontend/src/test/SystemConsole.test.tsx:72` 断言）。与 `src/api/ai_config.py` docstring"never written to disk or returned to clients"直接矛盾（docstring 未同步）。localStorage 对同源 XSS 无防护。
- **修复方向**：Key 只存后端内存（已如此），前端仅保存"是否已配置"标志；或在页面显著位置声明"仅本机演示、勿填真实付费 Key"；同步修正 ai_config 文档注释。

### F5. 口径与后端不一致："四十六大跨境品类"写死 vs API 返回 66（实测）

- **证据**：`frontend/src/widgets/MetricsGrid.tsx:27` 的 hint 写死"四十六大跨境品类"，而 value 取自 API 动态值（`src/api/services.py` 返回 `len(CATEGORIES)=66`）；`frontend/src/widgets/HeroPanel.tsx:24,36` 用 `Object.keys(snapshot?.categories ?? {}).length` 与 fallback 66 是正确的。页面上同时出现"46/66"两套口径（当前 8000 旧后端返回 46，见后端报告 B3）。
- **修复方向**：hint 改为从 `data.categories` 长度动态生成或删除写死文案；修复后端旧进程后复测。

### F6. 推荐排序前端/后端双实现，结果可能不一致

- **证据**：Top-N 排序逻辑在 `frontend/src/entities/dashboard/model.ts:47-65`（`recommendableTop()`）与后端 `src/api/services.py:633-641` 各实现一遍（verdict 序→六维分→增长→趋势→字典序 tiebreak）；`VERDICT_ORDER` 在 `frontend/src/entities/dashboard/model.ts:14` 重复定义（后端还有两处）。
- **修复方向**：排序收敛到后端接口返回已排序 Top-N，前端只展示；`VERDICT_ORDER` 由后端下发。

### F7. 离线分支硬编码汇率 7.1，与后端 7.15 漂移

- **证据**：`frontend/src/shared/api/client.ts:558,576`（离线贸易决策回退）写死 `* 7.1`，后端 `src/trade/cost.py:11` 为 `DEFAULT_FX_RATE = 7.15`。离线与在线演示毛利率/利润结果会不一致。
- **修复方向**：前端从 `/api/catalog` 或配置接口获取汇率，删除离线分支硬编码。
