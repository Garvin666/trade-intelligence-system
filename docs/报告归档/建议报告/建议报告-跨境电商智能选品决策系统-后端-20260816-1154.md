## 二、阻断级问题（答辩前优先处理）

### B1. 政策事件未标注品类 → 无关政策污染所有品类的决策结果（实测）

- **证据**：`src/trade/policy.py:954-973` `applicable_events_for()` 的逻辑是"事件标注了 categories 且不含当前品类才跳过"。实测 `load_policy_events()` 返回的 **23 个政策事件中 0 个带 categories**（`with_categories=0`），品类过滤条件永远不生效。
- **影响（实测）**："智能宠物喂食器 × 美国"的贸易决策报告中，`核心结论` 把"越南冷冻鱼片反倾销""印度大豆粕反倾销""韩国钢丝反倾销"等与宠物用品完全无关的事件全部列入"已生效"，有效税率从 6% 被抬到 **126%**、毛利率 -196.4%、决策 31.4 分"暂缓进入"。任何组合的决策都被市场级无关事件驱动，评委抽检即穿帮。
- **修复方向**：
  1. 为 `src/trade/policy.py` 内嵌事件表与 `output/policy/latest.json` 候选事件补 `categories` 标注；
  2. `applicable_events_for()` 对"categories 为空"的事件只做市场级提醒、**不参与税率重算**；
  3. 决策报告把政策事件按"与本组合相关 / 仅市场级"分组展示。

### B2. 数据口径自相矛盾：46 品类 / 690 组合 / 71,760 行 / 717,120 行 四套数字并存（实测 + 审计）

- **证据**：
  - 源码 `src/config.py` 实测 **66 个品类**（66×15×104=102,960 行，与 `data/processed/clean_data.csv` 实测 102,961 行含表头一致）；
  - 运行中的后端 `/api/categories`、`/api/summary` 实测返回 **46 品类、推荐 690 行（46×15）**——是旧代码进程（见 B3）；
  - `docs/技术文档.md:173` 写"717,120 条周粒度数据（46 品类 × 15 市场 690 组合）"；`docs/Demo优缺点评估报告.md:128` 写"71,760 行"（差 10 倍）；`docs/商业计划书.md:39,102`、`docs/数据分析报告.md:8,58`、`docs/项目大纲.md:96,169` 同样陈旧；
  - `src/app/dashboard.py:1382` 写"52 周年粒度"，与 `src/config.py:404`（`WEEKS_HISTORY = 104`）矛盾。
- **修复方向**：以 `len(CATEGORIES)` 为唯一事实源，批量替换 docs 为 **66 品类 × 15 市场 = 990 组合、102,960 行**；Streamlit 看板周数改为 `WEEKS_HISTORY` 或实际数据周数；核对并停掉旧进程（B3）。

### B3. 旧代码进程长期占用 8000 端口，新代码不生效（实测）

- **证据**：8000 端口被 `C:\Users\26717\anaconda3\python.exe scripts/run_api.py`（PID 15112，9:03:58 启动）占用，返回 46 品类（旧口径）；另有 `.venv` 的 run_api.py 进程（PID 27888）**未监听任何端口**（疑似端口被占后挂起），其日志 `tmp/complete-demo-backend.err.log` 记录了 `GET /api/dashboard-data?category=pet&market=us` 的 500（`KeyError: 'model'`，当前源码 `services.py:184` 已修复）。`start_complete_demo.ps1:190-222` 检测到 8000 健康就直接复用、不重启 → 改完代码重启仍是旧版本。
- **修复方向**：
  1. `Test-Health` 命中后增加代码版本指纹比对（如 CATEGORIES 数量/启动时间戳），不一致则提示并重启；
  2. `stop_complete_demo.ps1` 按命令行匹配清理所有 `run_api.py` 进程（不只 pid 文件）；
  3. 发布包与根目录共用端口检测，避免多副本并存。

## 三、重要级问题

### I1. 全局异常处理器吞掉 traceback，500 无日志可查

- **证据**：`src/api/app.py:908-917` 的 `@app.exception_handler(Exception)` 返回通用 500，处理器内**无任何 logging/traceback**，真实堆栈丢失（本次审计若非 err.log 恰好有 pandas traceback，B3 的 500 根因将不可见）。
- **修复方向**：处理器内先 `logger.exception("Unhandled error: %s", request.url.path)` 再返回 500。

### I2. 安全面：API 全无鉴权 + CORS 默认 `*`

- **证据**：`src/api/app.py:34-38` 默认 `allow_origins=["*"]`；70+ 端点（含收 Key 的 `POST /api/ai/config`、触发重任务的 `POST /api/jobs/*/start`、改全局权重的 `POST /api/scoring/weights`）均无鉴权。任一恶意网页在演示期间访问本机即可读取/替换配置或触发任务。
- **修复方向**：演示场景至少加随机启动 token 的简单鉴权中间件；或绑定 127.0.0.1 时校验 Origin；`/api/ai/config` 保持脱敏返回（`ai_config.get_status()` 已 mask，勿回归）。

### I3. 上传功能与 64KB 体积上限冲突

- **证据**：`src/api/middleware.py:15` 对**所有**请求按 `Content-Length > 65536` 直接 413；而"上传用户 CSV/JSON 仅基于用户数据生成报告"是主推特性，真实 CSV 极易超 64KB；且只查 Content-Length（chunked 可绕过），`/api/eda` 整文件 `file.file.read()` 入内存（`app.py:568`）。
- **修复方向**：上传端点单独放宽限额并流式读取、限制行数；中间件补 Transfer-Encoding 检查。

### I4. 环境自检"未通过" + 首次请求超时（实测）

- **证据**：`GET /api/check` 实测 `ok=30 warn=1 fail=1`，fail 为"依赖缺失：fg-data-profiling、scikit-posthocs、pyod"（当前 8000 进程运行在 anaconda 环境，缺 3 个 requirements.txt 声明包）；首次调用耗时超 20 秒。
- **修复方向**：统一用 `.venv` 启动并补齐 3 个依赖；quick 档去掉重量级检查或加缓存。

### I5. 推荐排序后端实现与前端重复，存在漂移

- **证据**：Top-N 排序（verdict 序→六维分→增长→趋势→字典序 tiebreak）在 `src/api/services.py:633-641` 与前端 `frontend/src/entities/dashboard/model.ts:47-65` 各实现一遍；`VERDICT_ORDER` 在 `src/models/recommend.py:11`、`src/api/services.py:79` 重复定义（前端还有第三处）。
- **修复方向**：排序收敛到后端 `recommendations` 接口返回已排序 Top-N，前端只展示。

### I6. 汇率魔法数字：7.15（后端）与前端 7.1 不一致

- **证据**：`src/trade/cost.py:11`（`DEFAULT_FX_RATE = 7.15`）vs `frontend/src/shared/api/client.ts:558,576`（离线回退写死 `* 7.1`）。
- **修复方向**：汇率由后端 `/api/catalog` 统一下发，前端删除硬编码。

### I7. 核心测试在项目主平台 Windows 上整体跳过

- **证据**：`tests/test_api.py:416,431,454,491,507,523`、`tests/test_search_api.py:55,77`、`tests/test_ai_speed.py:17` 共 9 处 `skipif(sys.platform == "win32")`，而本项目全套脚本（.bat/PowerShell/Streamlit）都以 Windows 为目标 → 四脑引擎、联网研究、AI 回退核心用例在主平台从未执行。
- **修复方向**：定位"四脑图表原生访问冲突"根因（疑似 plotly 图表序列化）后按用例修复；至少增加 GitHub Actions（Linux 全量）+ `pytest -m "not win_skip"` 统计口径。

### I8. 无 CI + 无 pytest 配置文件

- **证据**：全仓无 `.github/workflows`；根目录无 `pytest.ini`/`pyproject.toml` 的 pytest 配置（测试仅靠 `tests/conftest.py`）。AGENTS.md 声称 360 项测试但无自动化执行链。
- **修复方向**：加 GitHub Actions（Linux 跑 pytest 全量）；本地加 `pytest.ini` 固化 `testpaths=tests` 与 skip 标记。

### I9. 测试噪音：147 个 numpy RuntimeWarning（实测）

- **证据**：`tests/test_real_features.py` 触发 147 个 `RuntimeWarning: Mean of empty slice`（`numpy/lib/nanfunctions.py`）。
- **修复方向**：检查空切片来源并补保护（`np.nanmean` 前判空）。
