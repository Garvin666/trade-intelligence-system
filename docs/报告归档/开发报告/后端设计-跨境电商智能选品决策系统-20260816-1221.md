# 后端设计：跨境电商智能选品决策系统 — 建议报告修复

> 状态：按报告「答辩前 / 一周内」优先级执行可安全自动化修复；高风险项（鉴权、巨型模块拆分、git 提交）留待用户决策。

## 1. Problem Statement

后端审计报告实测出 3 个阻断级问题（B1 政策事件无品类标注污染决策、B2 数据口径四套数字并存、B3 旧进程占端口新代码不生效）、9 个重要级问题（I1-I9）与 9 个建议级问题（S1-S9）。目标：修复报告中列出的全部可安全自动执行问题，以测试与构建输出作为验收证据。

## 2. Solution

按报告行动清单逐项修复，核心为：

- **B1**：为品类特定政策事件补 `categories` 标注（映射 `src/config.py` 66 品类 code）；`evaluate_policy` 语义收敛为「有数值的市场级税率事件保留参与税率、无数值宏观事件仅市场级提醒、品类特定事件仅匹配品类参与」；决策报告按「与本组合相关 / 仅市场级」分组展示。
- **B2**：以 `len(CATEGORIES)` 为唯一事实源（66 品类 × 15 市场 = 990 组合 / 102,960 行），批量替换 docs 中的陈旧数字；Streamlit 看板周数改为 `WEEKS_HISTORY`。
- **B3**：`start_complete_demo.ps1` 健康检查增加代码版本指纹比对（CATEGORIES 数量 + 启动时间戳），不一致提示并重启；`stop_complete_demo.ps1` 按命令行匹配清理所有 `run_api.py` 进程。
- **I1-I9 / S2-S6、S9**：异常日志、上传限额、依赖补齐、排序/汇率单源化、pytest 配置与 CI、numpy 空切片保护、print→logging、裸 except 说明、死配置清理、字体探测、限流字典裁剪、导出文件名时间戳、占位补齐。

## 3. User Stories

- US1：作为评委，抽查"智能宠物喂食器 × 美国"决策报告时，不再看到越南鱼片/印度豆粕/韩国钢丝等无关政策进入"已生效"结论。
- US2：作为评委，核对 docs 时看到的数据口径与源码一致（66/990/102,960 行）。
- US3：作为开发者，改完代码重启 Demo 后，`start_complete_demo.ps1` 能识别 8000 端口上是旧版本并自动重启新代码。
- US4：作为开发者，后端 500 错误能在日志中看到完整 traceback。
- US5：作为用户，上传 >64KB 的 CSV 仍能生成报告。
- US6：作为用户，前端展示的推荐排序与汇率与后端一致（单源）。

## 7. API 契约与数据模型

- `PolicyEvent.categories`：既有字段，本次为快照事件补齐取值（品类 code 列表；空 = 市场级事件）。
- `/api/catalog`（或现有 trade 端点）：新增 `fx_rate` 字段下发 `DEFAULT_FX_RATE`，前端离线回退不再写死 7.1。
- 无新增端点；`evaluate_policy` 返回的 `PolicyAlert` 增加 `market_level_events`/`category_events` 分组字段（向后兼容，原字段不变）。

## 8. Implementation Decisions

1. **B1 数据标注**：`output/policy/latest.json` 中可明确映射品类的 6 个事件补 `categories`：越南冷冻鱼片→`food`、印度大豆粕→`food`、韩国钢丝→留空（市场级）、印尼风塔→`solar_energy`、中国木制卧室家具→`furniture`、美国多晶硅→`solar_energy`。
2. **B1 逻辑语义**：`evaluate_policy` 中「参与税率/成本重算」的事件 = 品类匹配事件 ∪ 市场级税率事件（`categories` 为空且 `verified` 且 `rate_ad_valorem>0 or min_duty_usd>0 or cost_adjustment_pct≠0`）；其余 `active` 事件仅进 `warnings` 与市场级提醒，不进 `titles` 核心结论与 `event_codes`（向后兼容测试 `test_us_policy_triggers_high_risk_with_min_duty` / `test_domestic_event_affects_policy_alert`）。
3. **B2 口径**：docs 中 46 品类/690 组合/71,760 行/717,120 行 全部替换为 66/990/102,960；`dashboard.py:1382` "52 周"改为 `WEEKS_HISTORY`。
4. **B3 端口**：`Test-Health` 命中后请求 `/api/check` 对比 `categories` 计数与进程启动时间；不一致则 Stop-Process 旧进程后重启新代码。
5. **I5/I6 单源化**：后端 `recommendations` 已返回排序 Top-N（带 rank），前端 `filterRecommendations` 只过滤不重排、直接用 `rank`；汇率由 `/api/catalog` 下发，前端删除 7.1 常量。
6. **I3 上传限额**：`BodySizeMiddleware` 对 `/api/eda` 与四脑上传路径放行至更大限额（如 20MB），补 `Transfer-Encoding: chunked` 检查；`/api/eda` 行数上限保护。
7. **I8 pytest 配置**：新增根目录 `pytest.ini`（testpaths=tests、markers、filterwarnings 收敛 147 个 RuntimeWarning 于测试输出）；新增 `.github/workflows/ci.yml`（Linux 全量 pytest + 前端 tsc/vitest）。

## 9. Testing Decisions

测试 seam：公共函数 `evaluate_policy` / `applicable_events_for` / `load_policy_events`（B1）；`GET /api/catalog`（I6）；前端 `recommendableTop` 行为改为纯透传后由 `filterRecommendations` 保留 rank（I5）。新测试必须独立于实现：B1 期望值来自品类语义（pet×us 不含鱼片事件；home×us 保留 de minimis 126%）；I9 期望空切片返回 nan 不告警。

## 11. 安全、性能与边界情况

- 上传放宽仅限白名单路径，其余请求维持 64KB 上限；行数上限防内存滥用。
- 汇率/排序单源化不改变已有响应字段，前端降级路径保留。
- 事件 categories 使用既有 66 品类 code，未知映射事件保持市场级，不臆造品类。
