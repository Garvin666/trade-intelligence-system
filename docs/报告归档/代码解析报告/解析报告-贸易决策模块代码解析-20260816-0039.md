## 一、核心摘要

`src/trade` 是一套**全离线演示口径**的跨境贸易决策引擎：以（品类 × 市场）为输入，串起政策风险、到岸成本、合规、IP、物流、舆情、CBAM、融资、冲突裁决、卖前体检、HS 速查与尽调，输出单个组合约 50 字段的决策字典。**主入口是 `decision.py::build_trade_decision`**（单组合），批量入口是 `report.py::build_trade_demo_report`（46 品类 × 15 市场 = 690 组合）。所有业务数据（税率、运价、认证、商标库、评论统计）均为模块内硬编码演示参数，代码中反复声明"真实场景可替换为官方接口"。

| `compliance.py` | `COMPLIANCE_MATRIX`：15 市场认证清单（FCC/CE/RoHS/PSE/KC/EAC/NOM 等，含成本、周期、必选标记）。`ComplianceAssessor.assess(market) -> ComplianceResult`：成本分=100-总成本/50，周期分=100-最长天数×2，`feasibility_score = 0.6×成本分 + 0.4×周期分`。 |

## 三、贸易决策完整数据流

```
输入（category, market, unit_price_usd, procurement_cost_cny）
  │  report.py：_default_inputs 默认价（fitness$45/appliance$36/outdoor$52，其余$28）
  │            _latest_inputs：取清洗数据每组合最新 price_median；采购成本=价×7.15×0.35
  ▼
decision.py::build_trade_decision（唯一主入口）
  1. cost 第一轮：基础关税 BASE_TARIFF_RATE[market][category]
  2. policy.evaluate_policy → PolicyAlert（风险级/有效税率/单件关税/成本调整/行动项）
  3. cost 第二轮：采购成本×(1+adjustment) + 有效税率 + min_duty → final 利润率
  4. compliance.assess → 准入可行性分 + 认证成本
  5. ip.screen → IP 风险          6. logistics.forecast → 运价/时效/风险
  7. preflight.build → 卖前体检     8. sentiment.analyze → 舆情分
  9. green.assess → CBAM 碳成本    10. credit.assess → 融资就绪分
  11. osint.assess_osint → 尽调清单 12. hs_code.lookup_hs → HS 速查
  13. conflict.resolve_trade_conflict → 冲突裁决（growth=50+情绪×50 传入）
  14. cost.compare_logistics → 三物流方案排序取最优
  ▼
输出 dict（~50 字段）→ report.py 汇总 690 组合落盘 / FastAPI /api/trade/decision
```

调用链：`scripts/run_trade_demo.py` → `report.build_trade_demo_report` → `decision.build_trade_decision`；`src/api/app.py` `/api/trade/decision` 直接调 `build_trade_decision`，`/api/trade/report` 走 services；`src/api/mcp_bridge.py` 调 `build_trade_decision` 与 `lookup_hs`。

## 四、关键技术实现细节

1. **政策风险量化**：新税率 = 基础税率 + Σ事件税率；单件关税 = max(售价×新税率, Σ中最大最低关税)；冲击% = (新关税−旧关税)/基础到岸成本×100 + 数值型成本调整Σ + 启发式调整（high 10%/medium 5%/low 2%，facilitate 取负，封顶 ±25%）；风险：≥15% high、≥8% medium、否则 low（对负冲击取 max(0) 不降级）。
2. **成本测算项**：采购（¥/7.15）+ 支付费（PayPal 4.5% / PingPong 0.6% / 连连 0.7%）+ 关税 + 物流（小包 25+12/kg、海运 12+6/kg、海外仓 8+4/kg，0.5kg 计）+ 认证合规；另输出汇率 ±5% 敏感性三档。
3. **冲突裁决规则**：7 信号加权；正信号均分−负信号均分 ≥25 为 high、≥12 为 medium 冲突；裁决优先级：风险信号（政策/物流/准入）任一 <60 且置信度 ≥0.75 → "降低备货规模/调整策略"；否则增长占优→保留但降优先级；否则小批量试单。
4. **证据闸**：`opportunity._evidence_metrics` 来源<2 条封顶 45 分、fallback 封顶 40 分、无快照给 40 分；`report._sanitize_report_payload` 落盘前剔除 api_key；`osint` 仅采信非 fallback/mock 的 1688 行。
5. **mock/回退**：policy 快照读取失败回退内置 2 事件；crawler 快照缺失时 evidence 走"谨慎"低分；IP 库无记录返回 low 但提示"需官方库核验"；hs_code `verified` 恒为 False；报告尾注明示"关税/汇率/费率/认证/物流均为可替换演示参数"。

## 五、问题与可疑点

1. **分发包缺文件（高风险）**：`src/api/services.py` 第 56–57 行**顶层** `from src.trade.catalog import ...`，但 `Demo运行包\src\trade\catalog.py` 不存在（仅存在于根目录 `src\trade\catalog.py` 与 `发布与材料\完整Demo运行包\src\trade\catalog.py`）。该分发包导入 services 即 ModuleNotFoundError，`/api/trade/catalog`、`/api/trade/autofill` 与统一后端启动受影响——**分发副本与主仓不一致**。
2. **HS 码名不副实**：名为 HS 速查，实为 HS4 位码（如 9403），且 `verified` 恒 False；`ip.py` 的 15 条库也只覆盖 5 品类。
3. **情绪双重计入**：decision 中 `growth_score=50+sentiment×50` 已含情绪，conflict 又单独传入 sentiment 信号（growth 0.25 + sentiment 0.10 权重）→ 情绪被加权两次。
4. **硬编码面广**：基础税率 15×46、运价序列、认证清单、商标库、评论统计、`DEFAULT_FX_RATE=7.15`、采购成本 0.35 系数、`C:\Windows\Fonts` 字体路径（report.py）均硬编码。
5. **健壮性**：`BASE_TARIFF_RATE[market][category]`、`MARKET_PROFILES[market]`、`MARKET_LANGUAGES[market]` 直接下标取值，新增品类/市场或数据含未知组合即 KeyError（report `_latest_inputs` 未防护）；`pd.Timestamp.utcnow()` 在 pandas 2.x 已弃用。
6. **口径一致性**：compliance 评分公式下几乎所有市场 feasibility 偏低（如美国 4700 成本 → 21 分），preflight 必选准入项因 FCC$2000>阈值恒 attention——演示叙事与"准入可行"建议存在张力；green 无 high 暴露路径，但 summary 仍统计 green_high；conflict 权重和 1.20 依赖归一化，易误导。
7. **政策事件时效**：`policy_watchlist()` 未传 policy_date，按当天过滤；若系统日期早于 2025-08-29，美国 de minimis 事件不进入任何测算与报告。

## 六、结论

模块分层清晰（policy/cost/compliance 为数据源，decision 为编排，report 为批量出口），量化口径自洽、可解释性强，适合演示；但全部参数为演示硬编码，真实场景需替换官方数据接口；当前分发包存在 `catalog.py` 缺失这一阻断性问题，且 HS 码、评分口径与情绪加权等细节需修正。
