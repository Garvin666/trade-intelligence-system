## 核心摘要

两个目录是"跨境电商智能选品决策系统"的两个独立可分发子系统：**四脑工作台**（Python 规则引擎 + 可选 AI 混合模式的选品分析引擎）与**贸易决策工作台**（纯前端计算模型 + 可选 Node.js 后端的贸易方案测算）。两者都采用"本地规则/模拟兜底 + 可选外部 AI 增强"的双轨设计，均可离线运行；主 Demo 通过 `iframe.srcdoc` 把两个子系统的完整 HTML 内嵌为单文件（52.6 MB），并以 `postMessage` + localStorage 共享一份全局 AI/统一配置。

## 1. 四脑引擎架构（`03_可运行系统/src/backend/four_brain.py`，1533 行）

### 1.1 四个大脑的分工

| 大脑 id | 名称 | 核心逻辑 | 依据 |
| --- | --- | --- | --- |
| `market` | 市场分析师 | 取品类/市场最新历史行与推荐行，用 `forecast_growth×1.1 + search_trend×0.9 + (80-competition)/2.2 + review_growth×1.1` 拼分，价格带匹配加减分 | `analyze_market`（L706） |
| `sentiment` | 舆情洞察官 | 查 `SENTIMENT_LIBRARY` 硬编码库（仅 outdoor/pet/fitness/small_appliance/home 五类，缺省回退 outdoor），基线分 + 评论增长 + 机会数 - 高影响差评数 | `analyze_sentiment`（L761） |
| `supply_chain` | 供应链评估师 | 到岸成本占售价中位数比例、MOQ×到岸成本 vs 预算、交付周期、认证数量加减分 | `analyze_supply_chain`（L791） |
| `finance` | 财务精算师 | 平台佣金表 `COMMISSION_RATES` + 广告/退货/汇率成本测算单件净利、毛利率、ROI、盈亏平衡件数、现金周期 | `analyze_finance`（L838） |

每个大脑输出 `score/direction/confidence/evidence/metrics/report`（Markdown 分报告，`_build_brain_report`）。

### 1.2 关键常量

- **DEFAULT_PAYLOAD**（L164）：默认测试产品为"便携除湿机 mini dehumidifier"（us 市场、25-45 美元、预算 2 万、目标毛利 35%、采购 9.5 元、MOQ 400、认证 FCC/CE/RoHS）。另有 `EXAMPLE_PAYLOADS` 6 套覆盖宠物喂食器、空气净化器、香薰机、瑜伽垫、户外电源。
- **KEYWORD_RULES**（L87）：46 类关键词→品类映射，用于 `infer_category` 推断品类（命中失败返回 `custom`）。
- **arbitrate**（L960）：加权投票 `market 0.40 + sentiment 0.30 + finance 0.30`，`置信度×分数` 加权求和，再按供应链分 <45 做风险扣分/降级（`(50-supply)/0.15`），输出 `verdict（推荐/谨慎/不推荐/有条件推荐）` 与冲突点列表。

### 1.3 规则引擎 vs AI 模式（FOUR_BRAIN_AI）

- 规则模式 `analyze()`：纯确定性计算，数据来自 `dashboard-data.json` 或用户上传数据（`normalize_data` 把 `latest_history` 归一为 `history`），响应 `generated_at="local-rule-engine-v2"`。
- AI 混合模式：
  - `analyze_with_ai`：先跑规则引擎得到"参考分"，再 `build_ai_prompts` 为四脑各生成 system/user 提示词（要求输出固定 JSON Schema：report/score/direction/confidence/evidence 等），`_run_ai_brains` 用 `ThreadPoolExecutor(max_workers=4)` 并发调用，单脑失败自动回退该脑规则结果并记 `ai_error`。
  - `analyze_with_research`：先跑研究代理（`ai_agent.py`）让模型自主决定调工具（web_search/fetch_page/load_dashboard_data/mock_market_data），工具结果追加上下文，最多 `max_steps` 轮，直到输出 `final` 中文总结；总结注入四脑提示词。`use_user_data/offline_only` 为真时完全跳过联网（`research.disabled=true`）。
- 启用方式：`GET ?ai=1` 或环境变量 `FOUR_BRAIN_AI=1`；未配 Key 时返回规则结果并标 `ai.used=false`，不报错（`_four_brain_analyze` L461）。

### 1.4 多提示词输入、分报告与综合输出

- `extra_prompt`（个性化要求）注入所有大脑提示词与综合报告（`render_markdown` 中"用户补充要求"和"个性化要求落实"章节）。
- 返回结构：`brains`（四脑结构化结果）+ `brain_reports`（四份独立 Markdown 分报告）+ `report`（综合 Markdown）+ `arbitration` + `charts` + `eda`。
- `output_format` 支持 full/brain/brief/charts；`output_charts` 选择 radar/bar/line/heatmap。

### 1.5 图表与数据工具

- `build_charts`（L1008）生成 4 张 ECharts 兼容配置：雷达图（四脑评分）、柱状图（评分+置信度）、折线图（市场指标）、热力图（品类×市场 search_index）。
- 数据工具（`data_tools.py`）：搜索 provider 支持 `mock/crawler/duckduckgo/duckduckgo_html/tavily/serpapi/generic`，默认 crawler（Wikimedia 搜索+pageviews，内部优先 `src.data.legal_crawler`，失败回退直连 Wikimedia，再回退 mock）；`fetch_page` 抓网页正文；`load_dashboard_snapshot` 读本地数据；`mock_search` 内置 6 组主题模拟结果且明确标注"模拟数据，需人工核验"。
- 用户数据上传：前端解析 CSV/JSON → `POST /api/four-brain` 带 `user_data` → 后端 `normalize_data` 后仅基于用户数据计算；`_build_eda_summary`（L480）纯标准库实现数据体检（缺失/去重/均值/3σ 异常点/二分组 A/B 差异）。

## 2. server.py 路由与 brain_bridge.py 的关系

`server.py`（800 行，纯标准库 `ThreadingHTTPServer`）是**独立可运行的精简后端**：

- GET 路由（`_route_get` L683）：`/api/health`、`/api/dashboard-data`、`/api/categories|markets|models|history|forecast`、`/api/model-metrics`、`/api/recommendations`、`/api/platform/rankings`、`/api/search/trends`、`/api/reviews/summary`、`/api/trade/export-value`、`/api/competition/index`、`/api/cost/metrics`、`/api/risk/overview`、`/api/market/compare`、`/api/scoring/weights`、`/api/feedback`、`/api/four-brain`、`/api/ai/status`。
- POST 路由：`/api/four-brain`（含 user_data 上传）、`/api/ai/test`、`/api/search/test`、`/api/feedback`、`/api/scoring/weights`。
- 静态服务：`/`（index.html 看板）、`/four-brain`（四脑工作台）、`/static/*`，带路径穿越防护。
- 保护机制：限流（180 次/60s/IP）、请求体上限、查询长度上限、白名单参数校验、15s GET 缓存、CORS、安全响应头。

**与主工程的关系**：主工程统一后端（FastAPI，`scripts/run_api.py`）中四脑路由由 `src/api/brain_bridge.py` 承接，它 import 的是 `src.four_brain` 包（`engine.py`、`ai_provider.py`、`data_tools.py`），并非本 Demo 目录的 `src/backend`。即：`src/backend/` 是**同源独立副本**（规则引擎逻辑与主工程 `src/four_brain/engine.py` 一致，README 注明"供 brain_bridge.py 调用"是说明性表述），用于便携独立运行；实际线上链路走主工程 `src.four_brain`。`brain_bridge.py` 比独立版多出 `_attach_real_evidence`（真实销量代理证据）、`search_history` 回填、`generate_template_report` 等能力。

### 3.1 方案预设 / 交易参数 / 风险假设

- `PRESETS`（app.js L61）：4 套预设（东南亚家居试单、美国宠物增长、欧洲小家电利润、低风险小批快反），`applyPreset` 套用后 `applyDefaults` 重算价格并 `commitInteraction` 记录影响。
- 交易参数：首批数量、售价、采购成本、重量、物流、广告费率（L89-122）。
- 风险假设：关税/税费、退货率、汇率波动、账期、库存天数（L124-147）。
- 业务策略 `STRATEGIES`：balanced/growth/profit/risk 四套权重（demand/profit/safety/cash）。

### 3.2 计算模型（`calculate` L1474）

- `demandScore`：推荐分×0.42 + 增长×1.05 + 搜索×0.68 + 平台 fit×0.22 + 市场销量×0.11 + 个性化 ± 价格溢价惩罚。
- 成本链：采购 + 物流（市场 logisticsFactor×重量因子）+ 平台佣金 + 广告 + 关税（采购+物流为基数）+ 退货损失 + 合规缓冲 + 固定成本 + 汇率缓冲 → `netProfit/margin/contribution/breakEvenUnits/cashDays`。
- 四维评分（需求/利润/现金/风险）按策略权重合成 `decisionScore`；`getDecisionStatus`（≥74 且毛利≥12% 且风险≤55 且现金≤105 天 → "建议进入"；≥62 → "小批试单"；否则"暂缓进入"）。
- **目标市场对比**：`renderMarketCompare` 对 15 个市场各跑一次 `calculate({market})`，按 decisionScore 取前 4 名渲染卡片，点击即切换市场（前端即时重算，与 AI 无关）。
- 平台适配排行、压力测试（乐观/基准/承压三档）、执行方案（renderActions）、客户版摘要（renderReport）同理全部由 `calculate` 派生。

### 3.3 经营沙盘

- `ACTIONS`（L112）：提价 3%、采购降本 5%、广告加码 2 点、切换空运、成本冲击模拟；`runAction` 记录操作前后 `decisionScore/netProfit/riskScore` 差值写入 `interactionLog`（最多 6 条），页面展示"决策分/净利润/风险"变化徽章。
- 路线图：SVG 地图 + 可拖动节点（`initRouteDragging`），按 ROUTES（海运/空运/海外仓）渲染不同节点链路。

### 3.4 AI 决策实现与接入方式

- 三层降级：①后端 `/api/analyze`（server.js 内 OpenAI 兼容调用，`callExternalAi`）→ ②前端浏览器直连（`browserDirectAiAnalysis` 直接用 fetch 调 `/chat/completions`，内置浏览器侧 Wikimedia/DuckDuckGo 检索）→ ③本地模拟 `localAnalyze`/`buildLocalAiAnalysis`。每层失败自动降级并标注 `ai_used/mode/降级`。
- 提示词：把 `scenario+catalog` JSON（截 8000 字符）+ 联网来源注入，要求输出 `{title,summary,confidence,signals,actions}` JSON。
- **AI 接入**：读取主 Demo 写入 localStorage 的 `trade_intel_ai_global`（`readGlobalAiConfig`，字段 base_url/api_key/model/timeout/search_provider 等）；后端环境变量为 `AI_BASE_URL/AI_API_KEY/AI_MODEL`（兼容 OPENAI_*），旧接口 `AI_API_ENDPOINT` 保留；`/api/status`、`/api/ai/test`、`/api/search/test` 供连通性测试。

## 4. 主 Demo 的内嵌集成方式

主 Demo `跨境电商智能选品系统_最优Demo.html`（52.6 MB 单文件）：

- 把三个子系统 HTML 作为**字符串常量**内嵌在自身脚本中（`WB_HTML` 四脑工作台 / `DASH_HTML` 看板 / `TRADE_HTML` 贸易决策），通过 `iframe.srcdoc` 注入（L52087556/L52090121/L52091240），iframe 无静态 src。
- "新窗口打开"用 `new Blob([HTML],{type:'text/html'})` + `URL.createObjectURL` + `window.open`；"全屏演示"切换 shell class。
- **统一配置协议**：主 Demo 顶部 `unified-config-bar`（通用/四脑/看板/贸易页签）写 `trade_intel_unified_config` 与 `trade_intel_ai_global` 到 localStorage，向各 iframe `postMessage('unified-config-apply')`；三个子系统收到后各自 `applyUnified*Config` 填表并回 `unified-config-ack`，加载完成时发 `unified-config-ready`，进入嵌入模式时加 `unified-embedded` class 隐藏自身左侧配置栏。
- AI Key 不落盘、不进 .env，仅存浏览器 localStorage 并同步到后端内存。

## 5. 发现的问题、不足或可疑点

1. **数据真实性弱**：`dashboard-data.json`（31.5 MB）与 `four-brain-browser-data.js` 均为合成数据（date 多为 2024-2026 周粒度、46 品类×15 市场×指标高度规律）；`SENTIMENT_LIBRARY` 仅 5 类硬编码、缺省回退 outdoor，其余品类舆情"张冠李戴"；`_cost_metrics`/`_market_compare` 等接口是原型估算（`source:"prototype_estimate"`），未接入真实榜单/汇率/物流 API。
2. **检索信号"确定性生成"**：`extract_search_history` 从搜索文本正则抠 CAGR/价格/竞争词，失败用默认值（growth=8%、price=40），再据此生成 26 周合成历史——即"搜索→伪造时间序列"，属于演示增强而非真实数据回填（代码注释已承认"无法直接拿到完整时间序列"）。
3. **AI 模式风险**：AI 输出 JSON 靠 `extract_json`（取首个 `{` 到末个 `}`）容错解析；研究代理若工具超步数则返回"已达最大调用次数"文案作为总结，可能带偏四脑提示词；浏览器直连模式把 API Key 暴露在前端（演示可接受，生产不可）。
4. **一致性缺口**：`使用说明.md` 称 backend 供 `src/api/brain_bridge.py` 调用，但实际 brain_bridge 引用的是 `src.four_brain` 包；`src/backend/` 是独立副本，两处规则引擎需手动同步（README 也承认"更新后请同步两份"）。Demo 包前端 `four-brain-browser.js` 又复制了一套 JS 规则引擎（5 品类精简版），三份实现存在漂移风险（如前端仅 us/eu/sea 三市场）。
5. **贸易决策 demo 疑点**：`package.json` 无任何依赖但 `server.js` 内部实现了完整代理 CONNECT 隧道（约 200 行），复杂度与"零依赖示例"定位不符；`CRAWLER_DATA_URL` 默认指向 `http://127.0.0.1:8000/api/crawler/signals`（主后端接口），未起主后端时静默失败（`fetchCrawlerEvidence` 吞异常返回 null）；README 中 cd 路径仍为旧路径 `D:\大学文件\26大创\贸易决策模拟Demo`。
6. **规模与维护**：主 Demo 单文件 52.6 MB（看板 40 MB 数据内嵌），首屏加载依赖 iframe srcdoc 全量注入，性能与浏览器内存压力大；四脑工作台 html 与 `deployment/static-site` 下副本、`发布与材料` 分发副本需多处同步。
7. **前端数据外置差异**：`01_可视化看板/dashboard.html`（40 MB）与 `03_可运行系统/data/dashboard-data.json` 为同一看板的"内嵌数据版"与"外置数据版"，版本一致性依赖 `run_daily_update.py` 重建，手工改动易不同步。

## 结论与建议

- 两个 Demo 均为"演示优先、离线可跑、AI 可选"的成熟演示工程：四脑引擎规则层逻辑完整可解释，贸易决策前端计算模型自成闭环，主 Demo 的单文件内嵌 + 统一配置协议设计精巧。
- 建议：答辩演示明确区分"合成演示数据/真实联网证据/模拟降级"三类来源（代码已多处标注，宣讲时强调即可）；后续如用于真实决策，需把三份规则实现收敛为一份、替换合成数据源，并评估单文件体积。
