## 一、关键脚本职责、参数、步骤与产物

### 1. run_api.py（25 行）— 统一后端启动
- 职责：启动统一 FastAPI 后端 `src.api.app:app`（含 REST API + React 前端 `/app` + MCP `/mcp` + 后台任务 `/api/jobs/*`）。
- 参数：无 CLI 参数；读环境变量 `BACKEND_HOST`（默认 127.0.0.1）、`BACKEND_PORT`/`API_PORT`（默认 8000）。
- 执行：插入项目根到 sys.path → `uvicorn.run("src.api.app:app", reload=False)`。
- 产物：无文件；运行中的 HTTP 服务（/docs 为 API 文档）。

### 2. run_daily_update.py（777 行）— 每日联网数据更新（核心，详见第二节）
- 参数：`--date`、`--provider`（默认 crawler，可用 SEARCH_PROVIDER）、`--offline`、`--skip-rebuild`、`--crawler-combos`（默认 `CRAWLER_DEFAULT_COMBOS=10`，注释 1-46）、`--skip-pipeline`。

### 3. run_pipeline.py（36 行）
- 职责：一键执行完整流水线（`src.pipeline.run_full_pipeline()`：数据→清洗→训练→预测→推荐）。

- 职责：生成贸易决策演示报告。读 `data/processed/clean_data.csv` → `src.trade.report.build_trade_demo_report`。
- 无参数；打印组合数、高中风险数、平均利润率、融资就绪分类；报告文件写于 `src.trade.report.OUTPUT_DIR`。

### 5. run_data_analysis.py（84 行）
- 职责：一键数据分析。`src.analysis.report.load_all` + `save_report`。

## 二、端到端数据更新链路（run_daily_update.py）

完整执行序列（[1/6]~[7/7] 打印编号）：

1. **[1/6] 数据重训**：`run_full_pipeline(force_regenerate=True, end_date=as_of)`；`--skip-pipeline` 则直接读现有 processed/forecast/recommendations（三者缺一报错退出码 2）。
2. **[2/6] 政策快照**：`refresh_policy_snapshot(policy_search=...或 None(offline), provider, policy_date)` → 落盘 `output/policy/latest.json` + `output/policy/daily/<date>.json`。
3. **[3/6] 真实数据源**：`collect_trends`→`output/trends/latest.json`；`collect_rankings`→`output/platform_rankings/latest.json`；`collect_customs_exports`→`output/customs/latest.json`；`build_anomalies_payload`→`output/anomalies/latest.json`；`collect_suppliers`→`output/suppliers/latest.json`（均带 offline 参数）。
4. **[4/6] 贸易决策报告**：`build_trade_demo_report(clean_df)` → `output/trade/trade_demo_metrics.json`。
5. **[5/6] 联网快照**：a) crawler signals：读 recommendations → `build_daily_combos(recs, crawler_combos)` → `build_snapshot` → `output/crawler/latest.json`（默认仅 Top10 组合，`--crawler-combos 46` 可全量）；b) **690 组联网检索**（46 品类 × 15 市场，`_daily_queries()`）→ `collect_daily_snapshot` → `output/daily_snapshots/<date>.json`（`--offline` 时用 `_offline_search` 写模拟结果并标注 fallback）；c) 市场日报 `output/market_daily/<date>.md` + 可选 webhook 推送。
6. **[6/6] 演示数据与状态**：`refresh_demo_payloads(...)` 更新 `output/demo/demo_data.json`（DEMO_DATA_JSON）并重写主 Demo `跨境电商智能选品系统_最优Demo.html` 内嵌数据；`write_data_status` 写 `output/data_status.json`（含 as_of、provider、fallback、各源状态、updated_files 清单）。
7. **[7/7] 重建与分发同步**（`--skip-rebuild` 可整段跳过）：`build_html_dashboard.build()` → 把 `output/dashboard-offline.html` 拷贝到 5~7 个 DASHBOARD_COPIES（跨境电商选品AI_Demo 看板目录、提交材料包、运行包 static-site/index.html 等）→ 同步四脑 `four-brain.html` → `rebuild_full_demo.main()` → `build_online_demo.main()`（失败仅打印跳过）→ `build_system_eval.main()`（失败跳过）→ `control_group.prepare_command()+score_all()+embed_demo_fallback()`（失败跳过）→ 同步运行包：最优 Demo、dashboard-data.json、data_status.json、当日快照、policy daily，以及 `RUNPACK_SOURCE_SYNC`（约 80 个源码/脚本文件）、`RUNPACK_ARTIFACT_SYNC`（约 27 项数据产物）、`RUNPACK_DIR_SYNC`（data/external/github 整目录）；存在嵌套 `发布与材料\完整Demo运行包\完整Demo运行包` 时再同步一份。

**可跳过项**：`--offline`（跳过全部真实联网：政策搜索用 None、快照用模拟）、`--skip-pipeline`（跳过第 1 步重训）、`--skip-rebuild`（跳过第 7 步重建与分发）、`--crawler-combos`（控制第 5 步 crawler 组合数）。注意：`--offline` 与 `--skip-pipeline` 可组合为文档推荐的"仅刷新快照/日报并重建"模式；但 690 组检索在 offline 下仍会执行（写模拟结果）。

**数据落盘位置**（均在项目根下）：`output/daily_snapshots/`、`output/policy/`、`output/trends/`、`output/platform_rankings/`、`output/customs/`、`output/anomalies/`、`output/suppliers/`、`output/crawler/`、`output/market_daily/`、`output/trade/`、`output/data_status.json`、`output/dashboard*.html`、`output/dashboard-data.json`，以及 `data/processed/`、`models/` 下的数据/模型产物。

## 三、完整 Demo 页生成链路

```
build_html_dashboard.build()          # 看板：dashboard.html(在线外置) + dashboard-offline.html(内联) + dashboard-data.json
  ↓ (dashboard-offline.html 作为 DASH_HTML)
embed_full_demo.main()                # 把看板字符串嵌入主 Demo（WB_HTML 四脑 + DASH_HTML 看板双 iframe）
  ↓
embed_trade_demo.main()               # 贸易决策单文件内联（先 build_trade_catalog 生成 catalog.js）→ TRADE_HTML
  ↓
polish_demo_content.main()            # 字符串级 UX 打磨（导航折叠/中英切换/政策徽标）
  ↓
build_online_demo.main()              # 在线版：DASH_HTML 置空，iframe 改指向 output/dashboard.html
rebuild_full_demo.main() = strip → replace WB_HTML → 上述四步（幂等重建入口）
```

- **离线单文件模式**：`跨境电商智能选品系统_最优Demo.html` 内联 WB_HTML（四脑工作台）、DASH_HTML（完整看板，含全部数据 JSON）、TRADE_HTML（贸易工作台）三份 HTML 字符串，双击即可用；看板页 `dashboard-offline.html` 数据内联。
- **在线外置数据模式**：`output/dashboard.html` 数据区为空，运行时 fetch `dashboard-data.json`（外置，可缓存、GZip）；`output/dashboard-online.html` 的看板 iframe 指向 `output/dashboard.html` 而非内嵌字符串，体积显著变小；后端 `/dashboard` 优先加载在线版。

## 四、complete_demo_refresh.ps1 启动时后台刷新

流程：必填 `-BackendPort`，可选 `-OfflineData` → 用 .venv 或系统 python 前台运行 `scripts\run_daily_update.py`（带 `--offline` 则跳过联网）→ **非 0 退出码则仅告警并退出，后端维持旧数据** → 成功后按端口查 `Get-NetTCPConnection` 找到监听进程 `Stop-Process -Force`，最多等 5 秒确认端口释放 → 重新调 `start_complete_demo.ps1 -NoBrowser -NoWait -Port <端口> -SkipDataRefresh` 重启后端（此时后端即可加载新数据与重建产物）。注意：该脚本本身是前台执行（刷新完成才重启后端），"后台"体现在由一键启动脚本以后台方式调用它。

## 五、control_group.py 顶级 AI 对照

- 统一入口：`run --global`，配置来自 `--api-key/--base-url/--model-id` 或环境变量 `OPENAI_API_KEY/OPENAI_BASE_URL/OPENAI_MODEL`（base-url 默认 `https://api.deepseek.com/v1`），缺少 key/model 时直接报错。
- `--mode lite`（默认）：12 组合轻量对照；`--mode full`：按市场分批跑完整 8280 格（46×15×12 评估格）。`--runs`（1-4，默认 2）、`--temperature`（0.2）、`--timeout` 可调。
- 执行：`src.control.benchmark.run_global_benchmark(...)`，产物 `output/control/score_summary.md` 与 `output/control/control_metrics.json`。
- 旧版兼容：`run --model/--all`（MODEL_REGISTRY 按 Key 逐个跑）、`web`（保存 DeepSeek 网页版回复后评分）；页面评测走 `/api/control/web/*` + `control_group.py web` 保留兼容但页面不再展示。run_daily_update.py 每日重建时也调用 `prepare_command()+score_all()+embed_demo_fallback()` 重算指标。

## 七、发现的问题 / 不足 / 可疑点

1. **硬编码 Windows 路径**：build_data_analysis_pdf.py、build_progress_pdf.py、build_outline_pdf.py 硬编码 `C:\Windows\Fonts\*.ttf`；embed_full_demo.py 后端探测硬编码端口 `[8000,8001,8010,8020]`（与 run_api 默认 8000 之外的端口需手动对齐）；verify_dashboard.py 默认 `http://localhost:8501`（Streamlit 端口，与现行统一后端不一致）；分发路径含日期 `提交材料包_整合优化版_20260805`，目录改名即失效。跨平台基本不可行（.bat/.ps1/字体路径）。
2. **重复定义漂移风险**：build_html_dashboard.py 自带 46 品类/15 市场字典，与 src/config.py 的 CATEGORIES/MARKETS 是两份拷贝（当前内容一致，但无校验）；embed_trade_demo.py 的 CATEGORY_ALIAS/MARKET_ALIAS 亦为硬编码映射。
3. **字符串标记脆弱性**：embed/rebuild 系列对主 Demo 依赖大量精确文本标记（`const WB_HTML = "`、`<button class="nav-link" data-target="workbench">四脑工作台</button>`、首个 `</style>` 等），模板一改即崩；rebuild_full_demo 的逆向剥离逻辑尤其复杂（含历史遗留清理）。
4. **性能与硬编码回退**：build_html_dashboard.collected_test_count 每次构建都子进程跑 `pytest --collect-only`（超时 120s），失败回退写死 269——该数字会过期；重建链路嵌套多层 try/except 仅打印"跳过"（build_system_eval、control_group、build_online_demo），失败不易察觉。
5. **启发式选文件**：embed_full_demo/rebuild_full_demo 用"根目录最大 *Demo.html"定位目标，存在多个 Demo 文件时会选错；embed_full_demo.find_dashboard 取第一个 `*/01_*/*.html` 候选。
6. **日志风格不一**：各脚本 print 中英混杂（`SKIP/REMOVE/OK/SYNC` 与中文混合），run_daily_update 步骤编号 [1/6] 与实际 7 步（含 7/7）不一致。
7. **offline 语义**：`--offline` 仅跳过真实检索，仍执行 690 组模拟检索并落盘完整快照与 data_status（标 fallback），产物体积与联网模式相同；`--crawler-combos` 默认 10 与文档"690 组联网检索"是两回事（690 组为品类×市场全量，crawler 为 Top10 推荐组合）。
8. **进程管理**：complete_demo_refresh.ps1 按端口杀 `OwningProcess`，若该端口由多进程/复用进程占用可能误杀；等待释放上限仅 5 秒。
9. **小瑕疵**：run_daily_update.py 第 493 行在 skip_pipeline 分支重复 `pd.read_csv(FORECAST_CSV)`；DEMO_DATA_JSON 在 src/config.py 与 run_daily_update.py 中各自做一次运行包判断（逻辑重复）。
