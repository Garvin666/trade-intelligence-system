## 2. 现状与根因（实测/代码核对）

### B4 根因
- `src/four_brain/engine.py::build_charts` 热力图对 66×15=990 组合各线性扫描 `data["history"]`（102,960 行），
  纯 Python 约 1 亿次迭代，重负载 + 55MB JSON 解析窗口内触发 Windows 原生访问冲突（0xc0000005，实测复现）。
- 后端进程无守护：崩溃后整站（REST + MCP + 前端托管）一起挂，前端只有裸 `Failed to fetch`。
- 测试用 9 处 `skipif(win32)` 掩盖，未隔离真实运行路径。

### B5 根因
- `src/checks.py::CONNECT_ENDPOINTS` 含 `("/api/dashboard-data", ...)`，`_probe_endpoint` 用 5s 超时拉全量 55MB；
  页面"环境自检"与 API 直调 `/api/check` 结果矛盾（30 ok vs 31 ok 差 1 fail=超时）。

### S9 根因
- 前后端字段名不一致，前端 fallback `?? "--"` 兜底导致整块 `--`：
  - `PreflightItem.to_dict()` 输出 `item/note`，前端读 `name/message`；
  - `OsintCheck.to_dict()` 输出 `item/note`，前端读 `title ?? name`、`status ?? note`；
  - `fx_sensitivity[label]` 输出 `{"汇率","利润率%"}`，前端读 `margin_pct ?? margin`。

## 3. 实现决策

| 决策 | 方案 | 理由 |
|---|---|---|
| D1 图表性能 | heatmap 预索引 `{(category,market): search_index}`，O(N)+O(990) | 消除 1 亿次扫描窗口，降低 native 崩溃概率，顺带提速 |
| D2 崩溃隔离 | 新增 `src/four_brain/worker.py`（multiprocessing spawn Pool(1)），`brain_bridge` 抽出 `_analyze_impl`，API 四脑端点默认走隔离执行 | 崩溃只杀 worker，主进程返回 503 + 结构化提示；测试直调 `_analyze_impl`/`analyze(inprocess)` 不受影响 |
| D3 看门狗 | `scripts/run_api.py` 增 `--watchdog`：父进程 spawn 子进程跑 uvicorn，崩溃自动重启（指数退避，上限 5 次/小时）；`start_complete_demo.ps1` 默认以 watchdog 方式拉起 | 演示现场崩溃自动恢复 |
| D4 轻量检查 | `/api/dashboard-data?meta=1` 返回 size/updated_at/rows 元数据；checks.py 的 dashboard-data 检查改为 meta + 本地文件存在性 | 两入口结果一致且 <1s |
| D5 字段对齐 | 后端 `to_dict()` 增加别名字段（保留原字段，不破坏既有断言与导出）：preflight 加 `name/message`，osint 加 `title/name/message`，fx_sensitivity 加 `margin_pct` | 单一事实源在后端，前端不动 |
| D6 skip 移除 | 隔离就绪后移除 4 文件 9 处 `skipif(win32)`，Windows 本地 + CI(Linux) 全量跑 | 消灭"已知缺陷用 skip 掩盖" |

## 6. 风险

- 子进程隔离引入每次请求 1~3s spawn 开销：仅在 API 四脑路径，演示可接受；可用 `FOUR_BRAIN_ISOLATED=0` 关闭（测试/调试）。
- watchdog 重启可能打断进行中的后台任务（daily_update）：重启仅发生在进程崩溃时，任务状态以落盘产物为准，可接受。
- 移除 skip 后若 Windows 本机仍有极少数环境崩溃：CI(Linux) 全量兜底 + worker 隔离保证进程存活，符合报告"移除 skip"要求。
